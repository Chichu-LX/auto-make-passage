# Experiment Code Run Agent

This Agent runs after the main benchmark has completed and `check-result-agent` has objectively passed every configured main metric gate. Server Schedule now runs only `main_benchmark`; this Agent owns all designed non-main computational experiments and seeds before paper writing.

The first invocation performs two gates. DeepSeek reviews explicit design claims for genuinely missing computational experiments using the strict `ExperimentCoverageDraft` contract. Deterministic code then checks that every designed non-main experiment is represented in the passed `CodeImplementationManifest` traceability. A design gap routes to Idea Design; a code gap routes to Code Make. Both routes subsequently repeat Code Review, the main server run and Check Result before returning here, so no unreviewed experiment code reaches a server.

When coverage is ready, the Agent reuses the immutable main server workspace and fresh Conda environment, re-probes current resources, transfers only generated job-spec JSON, reruns the reviewed foreground minimum demo, and launches every non-main experiment/declared-seed job with the existing managed `nohup` runner. It never constructs a shell training command and never deletes a remote directory.

Monitoring is persistent and user-gated. Active jobs return `in_progress` and schedule the next report within 12 hours. Completed reports preserve per-job status, exit code, raw finite JSONL metrics, bounded log snapshots, best checkpoint paths and deterministic per-experiment seed statistics. A result is accepted only when every designed job, seed and finite primary metric is present; numeric values are never generated by DeepSeek.

Artifacts are separated as follows:

- `design/<project>/experiments/coverage/`: design/code coverage audits;
- `project/var/runs/<run>/experiment_code_run/`: immutable launch manifests and job specs;
- `project/var/logs/jobs/<run>/experiment_code_run/`: bounded observed log snapshots;
- `design/<project>/experiments/results/`: JSON and Markdown result reports.

The six optional GitHub Skills are registry-only in the public repository. An explicit local sync
creates Git-ignored inspection copies, which remain inactive until their licenses and executable
contents are independently reviewed.
